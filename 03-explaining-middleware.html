Code Explanations (Human Language)

1. The Checkpoint Blueprint
We create a function that takes a role, then returns the actual Express middleware.
function authorize(requiredRole) { return (req, res, next) => { ... } }
2. The Decision Logic
If the user's role matches what the route wants, we call next() to let them in. Otherwise, we stop right there and reply with a 403 Forbidden code.
if (user.role === requiredRole) { next(); // Pass through } else { res.status(403).json({ ... }); }
3. Setting up the Doors
We tell Express: "When someone visits /admin, first run the authorize("admin") bouncer. If they pass, run the dashboard code."
app.get("/admin", authorize("admin"), (req, res) => { res.send("Welcome to Admin Dashboard!"); });
⚡

Crucial McMaster BDV101 Tip: The Server Freeze

Node.js runs your script into memory once. If you change your role from "admin" to "user" in index.js, the active server does not read the file again. You must press Ctrl + C in your terminal and run node index.js again to reload the script!

What is Middleware?

A piece of code that sits between receiving a request and sending a response. It can inspect, alter, allow, or reject requests.

Why use next()?

Without calling next(), the request will hang forever, and the browser will spin indefinitely. It acts as the gate key.

What is 403 Forbidden?

An HTTP status code. It means: "I know who you are, but you do not have permission to view this resource."
